# 里斯本丸号 · 永志纪念

互动纪念册第一版。深海蓝、石灰白与铜金色的传统纪念风格。

## 功能
- 收录所提供名单的全部 817 条记录，每行独立编号，保留同名人物。
- 姓名、原始资料检索；姓氏首字母索引；分页浏览。
- 点击姓名打开资料面板。缺失资料明确标注，未推断军衔、年龄或生平。
- 为单个人物献花，记录保存于 D1；同一已登录账号不重复计数。匿名访问时通过访客 Cookie 识别同一浏览器，清除 Cookie 后无法识别旧访客。
- 人物直达链接使用 `?person=lm-0001`。支持手机与键盘操作。

## 数据
`data/casualties.json` 来自 `lisbon_maru_casualties 3.csv`，保留 Name 与 Details 原文和对应 CSV 行号。
`public/data/lisbon_maru_casualties.csv` 是原文件副本。817 是文件记录数，不代表已核实的遇难总人数。
原始资料仍需独立史料核验。没有添加虚构人物照片或生平。
历史简述参考 https://www.lisbonmaru.org.uk/resource/html/Background%2Bto%2Bthe%2Bsinking%2Bof%2Bthe%2Blisbon%2Bmaru 。

## 运行
Node 22.13+，npm。
`npm run install:ci` 安装，`npm run dev` 预览，`npm run build` 构建。
献花功能需要先生成并应用 D1 迁移；本地库与线上库相互独立。
支持中文、英文、日文切换；使用 `?lang=zh`、`?lang=en`、`?lang=ja` 可直接打开对应语言。界面会记住语言选择，姓名与原始资料不做推测性翻译。

网站已设置为公开访问，获得链接的访客无需加入白名单。Sites 工作流负责发布并应用线上迁移，项目身份保存在 `.openai/hosting.json`。

## 验证
三语切换、语言 Cookie、语言与人物直达链接、切换后保留搜索、缺失资料与空结果提示、手机布局，以及匿名访客献花持久化已在本地浏览器验证。类型检查与 ESLint 通过。
浏览器智能检索接口进行了能力检测；当前验证浏览器不支持 WebMCP，因此该接口的注册和执行验证不可用，常规页面功能已验证。

## 部队单位浏览
新增“按姓名查看 / 按部队单位查看”两种模式；单位列表提供原始记录数，搜索可在选定单位内使用，缺失或无法辨识的单位归入“其他”。移动端使用单位选择列表。
分类规则位于 `lib/units.ts`：读取 Name 和 Details 两列中的明确单位文字，使用一份有限的原文件拼写变体表，不依据军衔或编号猜测单位。香港及新加坡皇家炮兵先于 Royal Artillery 匹配，防止混入更宽泛的炮兵分类。名单原字段和人物 ID 未修改，献花记录保持关联。

## 历史数据板块
`app/historical-data.tsx` 在纪念册与历史简述之间展示100点图与环形图，导航直达 `#historical-data`。中、英、日三语文字、人数与来源集中在 `lib/historical-data.ts`。
沿用用户提供的信息图数字，并以 LiMMA 历史资料核对1,816名船上战俘、828名死者、384名获渔民营救者及3名逃脱再捕者。604由1,816−828−384推导，381由384−3推导，页面注明计算口径。左图46/33/21个圆点显示四舍五入的比例；环图按照3/384的实际比例绘制（0.78125%）。384是渔民营救者这一子集，不是全部幸存者；其中381人随后被重新俘获。历史数字与817条文件记录明确区分。
图表与图例支持双向点击高亮：选中分类后，其余分类变淡，再次点击或按Esc取消。两张图独立维护选择；三语切换保留选中状态。每组SVG和每条图例均可通过键盘操作（Enter/空格），屏幕阅读器可读取选中状态与人数。小比例绿色环段具有扩大且透明的点击范围，实际图形比例不变。

## 船舱与战俘
`app/ship-holds.tsx` 提供独立板块 `#ship-holds`，使用用户提供的船形图片 `public/images/lisbon-maru-icon.jpg` 作为展开/收起入口。展开后可通过船舱标签或比例条切换 Hold No.1/2/3；支持键盘、触摸，收起或按Esc时恢复入口焦点，三语切换保留船舱选择。
`lib/ship-holds.ts` 集中管理20%/59%/21%、手写笔记中的人数及三语文字。人数来自用户提供的`IMG_3264.JPG`，原图仅保留在本地资料中，网站不提供原笔记图片或查看链接。1号舱366人（皇家海军366）；2号舱1,074人（皇家苏格兰团373、米德尔塞克斯团358、皇家工兵171、皇家通信兵129、其他43）；3号舱376人（皇家炮兵376）。各舱明细之和与舱总数一致，三舱合计1,816，四舍五入后的占比为20%/59%/21%。
网站明确区分笔记数据来源与LiMMA历史背景链接，不将笔记人数归因于LiMMA，也未由比例倒推人数或将其称为遇难比例。未修改CSV人物记录或历史伤亡图表。船形图片仅为互动入口，不被用作原船结构图或船舱定位依据。

## 地理与航程
`app/geography.tsx` 在船舱板块后新增 `#geography`，以SVG正射地球开场，自动旋转并依次聚焦香港、沉船坐标、东极岛一带和门司港。地点说明由`lib/geography.ts`集中管理，支持三语切换、暂停/继续、上一站/下一站、重播、拖动、键盘转动与缩放。讲述仅在板块进入视口且页面可见时运行；离开后暂停，结束后停在末站。遵循减少动态效果偏好，默认不自动播放。
用户已同意将原输入31°更正为采访中的`30°13′44.42″N 122°45′31.14″E`。经纬度由DMS计算为30.2290055556 / 122.75865；沉船位置与东极岛渔民营救地点分别讲述。前往日本的计划段用虚线，明确里斯本丸未抵达门司港。线条仅示意地点关系，不被描述为精确历史航迹；其他地点标记为概位。
地理底图`public/maps/world.geojson`由Natural Earth公开的110m国家数据缩减属性后生成（177个要素），渲染海岸轮廓，无浏览器外部地图服务或API密钥。来源、坐标采访、LiMMA营救资料和Richard Graham的门司港叙述在板块底部提供引用。`d3-geo`用于投影、球面裁剪与曲线；图片草图仅参考信息，未复制其配色。
已在本地浏览器检查完整自动讲述、暂停与重播、地点与地图标记选择、拖动/方向键/缩放、三语切换保留地点、320/390/768像素布局、减少动态效果设置、地图加载失败后的重试，以及离开板块暂停和返回后继续。类型检查与ESLint通过。
中国、日本轮廓与香港标记支持双向高亮：点击地图、颜色图例或地点卡片会同步选中对应国家/地区，其他色块变淡；中国关联沉船与东极岛地点、日本关联门司港、香港关联启航地。中国轮廓默认打开沉船坐标，已在东极岛地点时保留该地点。全球视角清除国家高亮；自动讲述与三语切换同步维护选中状态。从国家轮廓开始拖动会旋转地球而不会误选。已验证真实轮廓点击、图例/地点反向高亮、键盘和手机触摸。

地球底部新增独立红色“沉船点”图例，点击聚焦沉船坐标，与地图红点和沉船卡片双向高亮；东极岛营救地点不触发沉船点选中。地图、图例、地点标题及航程说明中的香港标注为“香港（英属）”/“Hong Kong (British)”/“香港（英国領）”，表示1942年航程的历史背景。

地图地点文字取消描边，使用明确的白色填充与深海蓝底板。仅弱化未选中的圆点，不降低地点文字透明度；按视口宽度保持标签至少约14像素，并对标签进行边界限制。标签在标记周围双向寻找最近的避让位置，选中地点优先；全球视图优先定位沉船标签。细引线随投影每帧更新，连接对应标记和标签，避免只向下堆叠造成位置误读。

## 事件拓扑
`app/event-topology.tsx` 与 `lib/event-topology.ts` 根据用户的图例与拓扑草图重绘原生SVG，无白色图片背景，沿用现有深海蓝、铜金、玫瑰红与鼠尾草色。导航 `#event-topology`；香港、东极岛、遇袭、三条初始人数分支、渔民营救、381/3后续分支、门司和英国共11个节点、10条连接。原定赴日航程使用虚线，实际事件进程使用实线；节点大小不表示人数比例。
点击节点追踪其上游与下游、点击图例高亮分类，介绍区域显示日期、人数和来源；支持键盘Enter/空格、Esc清除与事件选择列表，三语切换保留选择。手机横向滑动保持图中文字字号，外部页面不横向溢出。连线使用裁剪后的贝塞尔曲线，在主圆和地点副圆边缘结束，仅保留约2个SVG单位的描边余量，缩小断开的间隙；选中光环贴近节点，未用圆遮盖中心线。进入画面后按事件分支顺序展开连线、渐入节点，支持暂停/继续与重播；离开视口或页面后台时暂停，系统减少动态效果时显示完整静态图。点击节点增加短暂的光环反馈。营救和遇袭注释移出分支，归途曲线绕开文字。
数字复用历史数据板块：828/604/384与46%/33%/21%，381与3为384的子集，不能重复加总；198为渔民人数，参考新华社对亲历者的采访。目的地节点按语言显示：英文“UK”、中文“英国”、日文“英国”，去掉归途与见证的标题文字，不断言三人1943年同程直接回英国；LiMMA的Evans个人资料记载其经印度及加拿大后1945年访问英国。没有将384等同于最终安全幸存人数。

多语言文案应使用各语言自然表达，用户针对英文缩写的修改不应机械地应用到中文或日文。拓扑图目的地的图中文字、事件选择项和详情标题共享同一翻译来源。

## 中国渔民救援
新增 `#fishermen-rescue` 导航与独立板块，位于地理与航程之后、事件拓扑之前。`lib/rescue.ts` 集中提供五语文案、统计、岛屿概位与来源。198位渔民、46艘渔船、65船次和384位获救英国战俘均为两岛合计，使用新华社2015年亲历者报道核对，65是累计渔船出动次数。四组点阵逐点对应各类别单位，点击图表与颜色图例双向高亮并显示说明，不将不同单位相加，也不虚构两岛分别的人数。
地理关系图为朝北的墨卡托投影概位图，以官方2018年海岛名录的庙子湖岛（30°12.0′N 122°40.8′E）与青浜岛（30°12.1′N 122°42.3′E）定位；沉船点复用已确认坐标。连线仅示意出海救援方向，不声称还原65次真实航迹或每位落水者的位置，岛屿轮廓取自OpenStreetMap海岸线，保留来源与许可标注。地图点、连线和地点图例联动，提供选中介绍、坐标与恢复；支持键盘、手机横向浏览并自动将选中的地点滚入视口。三段简短叙述介绍出海、营救、岛上照料，后续命运链接回既有历史数据板块。统计、照料、岛名概位和沉船坐标分别链接真实来源。
已检查五语键名、占位符、单位与原始数量；198/46/65/384点阵实际圆点数；图表与地图联动、键盘、语言切换保留选中、手机触摸、320至1920像素布局、减少动态效果、地图连线与文字避让及浏览器错误。

救援图的两岛海岸线使用2026-10-01从OpenStreetMap API下载的闭合多边形：庙子湖way10008174（419顶点），青浜way9978571（248顶点）。`lib/rescue-islands.json`保留经纬度、来源、OSM版本与时间戳，界面以同一投影轻描轮廓；两岛官方概位均落在对应多边形内。未将现代海岸线声称为1942年海岸形态。轮廓可点击、键盘激活，图例、路线和说明同步；现代海岸线说明与来源标注提供五种语言。

船舱卡片的20%/59%/21%使用原生SVG环形图，pathLength=100，以对应比例绘制完整圆周的弧段，保留原有366/1074/376人数与部队数据。环形图和人数使用相同尺寸的指标列并保持中心对齐；人数与本语言的计数单位同行、基线对齐。检查了五语、320至1440像素布局与船形入口的展开/收起。

救援地点图以 `app/rescue-globe.tsx` 的动态地球作为入口，使用原有本地Natural Earth底图，三处发光点复用两岛概位与沉船坐标。在位置图进入视口后旋转6.5秒，再先朝向东极岛、以对数尺度放大3.4秒，随后用0.6秒透明过渡进入原救援地图。最终正射投影尺度为300000/cos(30.216°)，使三处地球标记与墨卡托局部图对应；手机选中地点的横向滚动量同时纳入地球相机。保留两岛真实轮廓、图例、连线、说明等交互。可通过地球、发光点、图例或进入按钮主动进入，返回地球后停留观看；支持暂停/继续、键盘、焦点衔接、五语，离开视口或隐藏页面停止动画，减少动态效果模式以点击直接进入替代自动放大。
